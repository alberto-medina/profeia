# 05 - MVP 2.0: Plataforma Docente

## Objetivo del MVP 2.0

Convertir el generador de clases (MVP 1.0) en una plataforma docente con
identidad propia: historial, banco de recursos, edicion visual y los
primeros pasos hacia la publicacion automatica en redes.

## Alcance funcional (suma sobre MVP 1.0)

- [ ] Editor visual de slides e imagenes (drag & drop basico, reemplazo de
      imagenes generadas, ajuste de texto en slides)
- [ ] Banco de clases (historial completo de clases generadas por el docente,
      con busqueda y filtros por materia/edad)
- [ ] Biblioteca de imagenes (imagenes generadas o subidas, reutilizables
      entre clases)
- [ ] Compartir clases con otros docentes (link de solo lectura o copia a su
      propia cuenta)
- [ ] Publicacion directa en YouTube, TikTok y otras redes, cuando las APIs
      de cada plataforma lo permitan (sujeto a aprobacion de developer
      accounts de cada red)
- [ ] Generacion de video ensamblado completo (si no se cerro en MVP 1.0)

## Fuera de alcance

- Generacion automatica de semanas completas de clases (eso es MVP 3.0)
- Multi-tenant institucional (colegios con varios docentes administrados
  centralmente) - se puede evaluar como extension de este MVP si surge
  demanda, pero no es bloqueante

## Criterio de exito

Un docente puede:

1. Ver el historial completo de sus clases generadas.
2. Reutilizar imagenes de clases anteriores en una clase nueva.
3. Editar visualmente una slide sin volver a generar todo el contenido.
4. Compartir una clase con un colega.
5. Publicar un video generado directamente en al menos una red social desde
   la app (sujeto a disponibilidad de API).

## Cambios en el modelo de datos

Se agregan sobre el esquema de MVP 1.0:

- `biblioteca_imagenes` (imagenes reutilizables por docente)
- `clases_compartidas` (relacion docente_origen / docente_destino / clase_id)
- `publicaciones` (registro de publicaciones realizadas: red social, url,
  estado, fecha)

## Endpoints backend adicionales

```
GET    /clases/historial            -> historial completo con filtros
GET    /biblioteca/imagenes         -> lista imagenes guardadas
POST   /biblioteca/imagenes         -> sube/guarda una imagen
POST   /clases/{id}/compartir       -> genera link o copia a otro docente
POST   /clases/{id}/publicar/{red}  -> dispara publicacion en red social
GET    /clases/{id}/slides/editar   -> contenido editable de slides (estructura)
PUT    /clases/{id}/slides/editar   -> guarda cambios del editor visual
```

## Notas de implementacion

- El editor visual puede empezar simple: edicion de texto en slides y
  reemplazo de imagen por otra de la biblioteca, sin animaciones complejas
  todavia.
- La publicacion automatica depende de aprobaciones externas (Meta, TikTok,
  YouTube Data API); conviene dejar esta funcionalidad detras de un feature
  flag por red social, activable a medida que se consiguen los accesos.
- Mantener la misma separacion contenido/multimedia del MVP 1.0; el editor
  visual edita la capa multimedia, no la pedagogica.
