# 04 - MVP 1.0: Generador de Clases

## Objetivo del MVP 1.0

Validar el flujo central: un docente escribe un prompt y recibe una clase
completa, editable, lista para exportar en PDF, PPTX y con voz narrada.

Este MVP **no** incluye edicion visual avanzada, banco de clases compartido
ni publicacion automatica a redes (eso es MVP 2.0).

## Alcance funcional

- [x] Login / registro de docente
- [x] Perfil del docente (nombre, materia principal, idioma)
- [x] Crear una clase desde un prompt
- [x] Generar contenido pedagogico:
  - Objetivos
  - Guion
  - Ejemplos
  - Actividades
  - Evaluacion
- [x] Editar el contenido pedagogico en cualquier momento del flujo, no solo
      al generarlo por primera vez (ver "Edicion en cualquier momento" mas
      abajo)
- [x] Generar voz (TTS) a partir del guion
- [x] Generar imagenes de apoyo
- [x] Generar diapositivas (slides)
- [x] Exportar a PDF
- [x] Exportar a PowerPoint (PPTX)

## Fuera de alcance (explicitamente)

- Editor visual avanzado de slides/video
- Banco de clases compartido entre docentes
- Publicacion automatica a YouTube/TikTok/Instagram via API
- Generacion de video ensamblado (se puede dejar como flag deshabilitado o
  como mejora incremental dentro del mismo MVP si el tiempo lo permite, pero
  no es bloqueante)

## Criterio de exito

Un docente puede, en menos de 5 minutos:

1. Escribir un prompt describiendo la clase que necesita.
2. Recibir contenido pedagogico coherente y editable.
3. Generar voz e imagenes de apoyo.
4. Descargar un PDF y un PPTX listos para usar en el aula.

## Modelo de datos minimo (ver doc 07 para detalle completo)

- `docentes` (perfil)
- `clases` (prompt, parametros, contenido generado en JSON, estado)
- `recursos_generados` (tipo: voz/imagen/slide, url en Storage, clase_id)

## Endpoints backend minimos

```
POST   /auth/login
POST   /auth/registro
GET    /perfil
PUT    /perfil

POST   /clases                  -> crea clase desde prompt, devuelve contenido generado
GET    /clases                  -> lista clases del docente
GET    /clases/{id}             -> detalle de una clase
PUT    /clases/{id}              -> edicion manual del contenido generado

POST   /clases/{id}/voz          -> genera audio TTS
POST   /clases/{id}/imagenes     -> genera imagenes de apoyo
POST   /clases/{id}/slides       -> genera estructura de diapositivas
POST   /clases/{id}/exportar/pdf  -> genera y devuelve URL del PDF
POST   /clases/{id}/exportar/pptx -> genera y devuelve URL del PPTX
```

## Pantallas Kivy correspondientes (ver doc 02)

- Pantalla 1: Que queres ensenar hoy? (prompt + parametros)
- Pantalla 2: Contenido generado (editable)
- Pantalla 3: Elegir recursos a generar
- Pantalla 4: Configuracion de voz
- Pantalla 6 (parcial): Exportar PDF / PPT unicamente en este MVP

## Edicion en cualquier momento

La edicion del contenido pedagogico (Pantalla 2) no esta limitada al momento
inicial de creacion. El docente puede volver a editarla desde la Pantalla 6
(Exportar) usando el boton **"EDITAR CLASE"**, incluso despues de haber
generado voz, slides o exportado PDF/PPTX.

Detalle de implementacion (frontend):

- `EstadoApp.pantalla_retorno_edicion` guarda a que pantalla volver despues
  de guardar una edicion: `"recursos"` en el flujo normal (primera vez) o
  `"exportar"` cuando se entra a re-editar.
- La Pantalla 2 carga el contenido vigente en `on_pre_enter`, asi que
  siempre muestra los datos actualizados sin importar desde donde se entro.
- En modo re-edicion aparece un boton **"CANCELAR"** que descarta los
  cambios no guardados y vuelve sin tocar el contenido ya persistido.
- Si el docente ya habia exportado PDF o PPTX antes de editar, la Pantalla 6
  marca esas exportaciones como desactualizadas al volver, para que sepa
  que tiene que generarlas de nuevo con el contenido editado.

El backend no necesita cambios para esto: el endpoint `PUT /clases/{id}`
(ver mas abajo) ya soporta guardar el contenido en cualquier momento, no
solo una vez.
